# Dayly Style Skill

Use this skill whenever editing UI, components, screens, modals, cards, navigation, or visual polish.

## Visual Identity

Dayly should feel:

- premium
- dark
- minimal
- focused
- gamified
- dopamine-rich but not childish

The visual inspiration is:

- Forest-style productivity
- Snapchat streak motivation
- soft RPG progression
- luxury black/grey/silver UI
- subtle orange accent

## Style Rules

Preserve the existing app identity.
Do not introduce a completely different design system.
Use the existing:

- ThemeContext
- spacing constants
- typography constants
- dark/light colour system
- existing component patterns

## UI Principles

Prefer:

- black/dark grey backgrounds
- soft grey cards
- silver/white text
- rounded cards
- subtle borders
- soft glow
- clean rings/progress indicators
- minimal icons
- consistent spacing
- haptic feedback for important actions

Avoid:

- childish colours
- heavy gradients everywhere
- random neon colours
- cluttered screens
- changing the whole layout unnecessarily
- new UI libraries unless absolutely necessary

## Component Polish Checklist

When editing a component:

- match existing font families
- use theme colours, not hardcoded colours where possible
- use spacing constants
- use consistent border radius
- add loading/empty/error states where relevant
- keep mobile layout simple
- avoid huge files
- extract reusable components only when it reduces complexity

## Output Rules

Before making UI changes:

1. Inspect relevant files.
2. Identify existing style patterns.
3. Make the smallest improvement that fits the current design.
4. Do not rewrite unrelated components.
